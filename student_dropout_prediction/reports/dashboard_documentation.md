## 1. Overview

Stage 9 adds a comprehensive **Early Warning Risk Dashboard** to the existing web application. The dashboard provides academic advisors and support staff with an aggregated, visual overview of predicted student dropout risks — without storing or displaying any personal identifiable information.

> [!IMPORTANT]
> All student records shown in the dashboard are **anonymized**. Reference IDs are system-generated codes (e.g., `STU-BENCH-0001`). No names, contact details, addresses, or other personal identifiers are stored or displayed anywhere in the system.

## 2. Dashboard Components

### 2.1 KPI Stat Cards

Four summary cards displayed at the top of the dashboard:

| Card | Description |
|:--|:--|
| **Total Students Evaluated** | Total number of prediction records in the currently selected data source |
| **Low Risk Students** | Count and % of students with predicted dropout probability `< 30%` |
| **Medium Risk Students** | Count and % of students with predicted dropout probability `30% to < 60%` |
| **High Risk Students** | Count and % of students with predicted dropout probability `>= 60%` |

### 2.2 Visual Charts (Chart.js)

Three interactive charts:

| Chart | Type | Description |
|:--|:--|:--|
| **Risk Distribution** | Doughnut / Pie | Shows the proportional split between Low, Medium, and High risk tiers |
| **Students Per Risk Category** | Bar chart | Absolute number of students in each risk category |
| **Dropout Probability Distribution** | Histogram (bar) | Distribution across 5 probability bins: 0–20%, 20–40%, 40–60%, 60–80%, 80–100% |

### 2.3 Student Risk Table

A paginated, filterable table showing anonymized student evaluation records:

| Column | Description |
|:--|:--|
| **Reference ID** | System-generated anonymized ID (e.g., `STU-BENCH-0001`, `STU-LIVE-0001`) |
| **Timestamp / Source** | When the prediction was made, or "UCI Benchmark Evaluation" for test cohort |
| **Risk Category** | Color-coded badge: 🟢 Low Risk / 🟡 Medium Risk / 🔴 High Risk |
| **Dropout Probability** | Percentage probability output by the Random Forest model |
| **Predicted Class** | Binary class label: `Graduate / Enrolled (Class 0)` or `Dropout (Class 1)` |
| **Status** | Advisory action tag: `On Track` / `Advisory Check` / `Review Recommended` |

### 2.4 Filter Bar

Four filter buttons:
- **All Students** — Show all records
- **🟢 Low Risk** — Show only Low Risk records
- **🟡 Medium Risk** — Show only Medium Risk records
- **🔴 High Risk** — Show only High Risk records

Selecting a filter updates the table contents and the displayed record count.

### 2.5 Early Warning Overview

A static information section providing:
- A description of each risk tier and what it means for a student
- Specific, constructive support recommendations per tier (non-punitive)
- A prominent ethical disclaimer box listing key limitations

## 3. Data Sources

The dashboard supports two data sources, switchable via toggle buttons at the top of the page:

### 3.1 Benchmark Cohort (Default)
- **What it is:** The champion Random Forest model applied to all **885 held-out test students** from the UCI repository dataset (`dataset/test_data.csv`).
- **Is it real data?** Yes — these are the same real students used to evaluate the model in Stage 6.
- **Is it fake?** No — predictions are computed by the actual trained ML model using genuine student records.
- **Privacy:** All 885 records use anonymized reference IDs (`STU-BENCH-XXXX`). No personal details are stored.
- **Refresh:** The benchmark cohort is computed **once** at server startup and cached in memory.

### 3.2 Live Session Predictions
- **What it is:** Each time a student record is submitted via `POST /predict` (from the Home page form), an anonymized prediction record is appended to `models/predictions_history.json`.
- **Is it persistent?** Yes — records are saved to disk and persist between server restarts (up to 500 records).
- **Is it fake?** No — only records generated by real form submissions appear here.
- **Privacy:** Live records use anonymized reference IDs (`STU-LIVE-XXXX`). No personal names or contact details are saved.

## 4. How Counts Are Calculated

All counts and percentages are calculated server-side by the `compute_dashboard_metrics()` function in `app.py`:

```python
high_count   = number of records with risk_category == "High Risk"
medium_count = number of records with risk_category == "Medium Risk"
low_count    = number of records with risk_category == "Low Risk"

high_pct   = round((high_count / total) * 100, 1)
medium_pct = round((medium_count / total) * 100, 1)
low_pct    = round((low_count / total) * 100, 1)
```

**Risk category assignment** (defined in `src/predictor.py`):
- `< 30%` dropout probability → **Low Risk**
- `30% to < 60%` dropout probability → **Medium Risk**
- `>= 60%` dropout probability → **High Risk**

## 5. API Endpoint Reference

### `GET /dashboard`
Renders the dashboard HTML page.

### `GET /api/dashboard`
Returns aggregated dashboard data in JSON format.

**Query Parameters:**

| Parameter | Options | Default | Description |
|:--|:--|:--|:--|
| `source` | `benchmark`, `live` | `benchmark` | Data source to query |
| `filter` | `all`, `low`, `medium`, `high` | `all` | Filter records by risk tier |
| `page` | integer ≥ 1 | `1` | Page number for table pagination |
| `page_size` | 1–200 | `50` | Records per page |

**Example Requests:**
```
GET /api/dashboard
GET /api/dashboard?source=live
GET /api/dashboard?source=benchmark&filter=high
GET /api/dashboard?source=benchmark&page=2&page_size=25
```

**Response Structure:**

## 8. Limitations

| Limitation | Details |
|:--|:--|
| **No MySQL database** | Live prediction records are stored in a lightweight JSON file (`models/predictions_history.json`) up to a maximum of 500 entries. MySQL integration is planned for Stage 10. |
| **Benchmark cohort is static** | The 885-student benchmark cohort is computed once at server startup and cached. It does not update during the session unless the server restarts. |
| **Filter only updates table** | Dashboard filter buttons update the table and record count only. The KPI summary cards and charts always reflect the full cohort (not filtered). This is intentional — the charts provide a cohort-level overview. |
| **Pagination default** | Default page size is 50 records. For the benchmark cohort (885 records), users will need to navigate 18 pages to see all Low Risk records. |
| **Model accuracy** | The Random Forest model achieves ~84% accuracy. Approximately 16% of predictions may be incorrect. All results are clearly labeled as estimates. |

## 9. Ethical & Privacy Summary

- No student names, contact details, addresses, phone numbers, or personal identifiers are collected, stored, or displayed.
- All reference IDs (`STU-BENCH-XXXX` / `STU-LIVE-XXXX`) are system-generated anonymization codes with no real-world linkage.
- Risk predictions are explicitly labeled as probabilistic estimates for decision-support use only.
- The dashboard does not recommend punitive or disciplinary actions. All suggestions are constructive academic support measures.
- Authorized academic staff are encouraged to review individual cases before taking action.
